## 关键决策与踩坑

### 1. 中断信息用 `aget_state()` 取，不要自己合并 updates 分片

`astream(stream_mode="updates")` 每个分片只是**单节点的增量**，`trace` 又用了 `lambda x, y: x + y` 自定义 reducer，自行合并容易出错。
`langgraph/types.py:700` 的 `StateSnapshot.interrupts` 是**顶层字段**，因此：

```python
snapshot = await graph.aget_state(config)
result = dict(snapshot.values)
if snapshot.interrupts:
    result["__interrupt__"] = snapshot.interrupts
```

状态与中断都取自 LangGraph 权威来源，行为与 `ainvoke` 等价。**这是本工程可复用的模式。**

### 2. `upsert_candidate()` 必须在图运行之后调用

姓名来自图内 `extract_node` 的抽取结果，图跑完才有值。
`extract_node` 位于 `validate_node` 之前，所以 **WAITING_REVIEW 分支同样能拿到姓名**。

### 3. uvicorn 默认不配置 root logger，`basicConfig` 可生效

uvicorn 的 `LOGGING_CONFIG` 只配置 `uvicorn` / `uvicorn.error` / `uvicorn.access`，不动 root。
因此在 `app/main.py` 模块级调用 `logging.basicConfig()` 即可让应用 logger 输出到终端。

### 4. 运行中的后端若是无 `--reload` 启动，改动不会生效

本次发现 8000 端口上的旧进程命令行是 `python -m uvicorn app.main:app --host 127.0.0.1 --port 8000`（无 `--reload`），
表现为 `/api/samples` 仍返回 200。**重启后即正常**。排查手法：`Get-CimInstance Win32_Process -Filter "ProcessId=<pid>" | Select-Object -ExpandProperty CommandLine`。

## 已知环境问题（非代码缺陷）

### 1. `backend/.env` 的 `DASHSCOPE_MODEL=qwen3.8-max` 不存在

DashScope 返回 `400 InvalidParameter: url error`。
同文件中注释已写明可用值：`qwen-plus` / `qwen-max` / `qwen-turbo` / `qwen3-max`。
**未擅自修改 `.env`**（属用户本地配置），需用户自行改回 `qwen-plus`。

### 2. `school_tier` 抽取不稳定 → `test_jia_completes_with_105` 可能偶发失败

同一提示词对甲（电子科技大学）连续 3 次抽取，`school_tier` 结果依次为
`double_first_class` / `None` / `None` —— 是模型非确定性，与提示词改动无关。
已有的兜底：`rules.yaml` 的 `school_tier.unknown = 8`，因此缺失时得 8 分（93 分）而非 0 分。
**注意：该用例存在偶发失败风险。**
