# 新增删除简历功能

日期：2026-09-22
涉及模块：backend / frontend

## 需求

在历史记录里可以删除简历（只能在历史记录里删，四张统计卡弹窗里不可删）。

## 改动清单

### 后端

| 文件 | 改动 |
|---|---|
| `backend/app/services/storage.py` | 新增 `delete_run(thread_id) -> bool`：按 thread_id 删 runs 行，返回是否删到 |
| `backend/app/api/candidates.py` | 新增 `DELETE /api/candidates/{thread_id}`：调 `delete_run`，删不到抛 404 |

### 前端

| 文件 | 改动 |
|---|---|
| `frontend/src/api/agent.ts` | 新增 `deleteCandidateRun(threadId)` |
| `frontend/src/components/HistoryList.tsx` | 加 `deletable?: boolean` + `onDelete?: (threadId: string) => void`；每行右侧红色垃圾桶图标按钮，用 `Popconfirm` 包一层二次确认；按钮 `stopPropagation` 避免误触列表项 click |
| `frontend/src/components/HistoryModal.tsx` | 加 `deletable` / `onDelete` prop 透传给 `HistoryList` |
| `frontend/src/pages/Dashboard.tsx` | 新增 `handleDeleteHistory`；`HistoryModal` 传 `deletable={listKey === 'all'}`（只有头部「历史记录」按钮打开的弹窗才能删，统计卡弹窗一律不可删）；删完调 `refreshStats()` + `refreshHistory()`；如果删的是当前 result modal 正在展示的那条，顺手关掉 result modal |

## 关键决策

| # | 决策 | 依据 |
|---|---|---|
| 1 | **只删 runs 表，不删 candidates 表** | 历史列表用 `runs LEFT JOIN candidates`，删 runs 行就自然从列表消失；candidates 表保留孤立行无害，也避免万一有人想 restore |
| 2 | 删除权限由前端控制，后端不区分来源 | 后端鉴权不在本项目范围内；前端控制 `deletable={listKey === 'all'}` 就够了，后端 DELETE 接口始终开放是合理的（本地开发工具） |
| 3 | Popconfirm 必须在 `stopPropagation` 按钮外层再包一次 `stopPropagation` | 列表项整体 click 是打开详情，垃圾桶按钮的 click 会冒泡触发详情弹窗；按钮本身 `onClick.stopPropagation()` 只挡住 Popconfirm 触发器，Popconfirm 确认按钮还要在 `onConfirm` 里再调一次 `e.stopPropagation()`，双重保险 |
| 4 | 删后清 result + review 两个弹窗 | 虽然概率低，但如果 result modal 正在展示刚被删的 thread_id，刷新后 `getCandidateRun` 会 404；顺手关掉最省事 |
| 5 | MemorySaver 图状态不清理 | 是进程内内存态，删 SQLite 行不会动它；如果有人拿已删 thread_id 去 resume，LangGraph 会自己报错（thread 状态不存在），属边缘情况不需额外处理 |

## 踩坑

- **DELETE 后列表条数还是 50**：不是 bug。`list_runs(limit=50)` 硬限，刚删 1 条但总数还是 >50，刷新后依旧返回 50 条。`/api/stats` 的 total 已正确减 1（57 → 56），统计卡数字会同步。列表条数要真变 49 得删掉当前 50 条里**最后一条**。
