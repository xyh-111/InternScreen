# 移除在读状态判定模块

日期：2026-09-22
涉及模块：backend

## 需求

在进入系统之前会经历一轮初筛，默认进入本系统的简历候选人都是在读状态，所以删掉「是否在读」这整套判定逻辑。

## 改动清单

### 删除的内容

| 位置 | 删除的东西 |
|---|---|
| `app/config/rules.yaml` | `hard_filter.require_in_school: true` |
| `app/services/rule_engine.py` | `run_rules()` 里第 230-231 行的硬性条件检查 `if hard["require_in_school"] and not resolve_in_school(fields): hard_reasons.append("非在读")`；整个 `resolve_in_school()` 函数（明示优先 + `education_end` 兜底）；整个 `_parse_year_month()` 辅助函数；整个 `_EDU_END_RE` 正则；模块 docstring 里关于在读判定的描述；`from datetime import date` 导入 |
| `app/graph/state.py` | `ExtractedFields` 里 `in_school`（`Optional[bool]`）和 `education_end`（`Optional[str]`）两个字段 |
| `app/tools/extract_tools.py` | 提示词里第 8 条 `education_end` 抽取规则（编号 8，原来的 9-13 顺延为 8-12）；`_JSON_PROMPT` 键列表里的 `in_school`、`education_end` |
| `tests/test_rule_engine.py` | `resolve_in_school` import + `date` import + 11 个测试函数（test_stated_in_school_beats_expired... / test_future_education_end... / test_run_rules_accepts_time_derived... / test_run_rules_rejects_graduated... 等） |

### 保留的内容（有意为之）

- `JIA_FIELDS` / `YI_FIELDS` / `BING_RESOLVED_FIELDS` 里的 `"in_school": True` 没删——留着是无害的冗余字段，删了还得改三行 fixture；且 `run_rules()` 不再读取它
- 前端 `RunFields` 接口里的 `in_school` / `education_end` 没删——老记录的 `fields_json` 里还可能有这两个键，TS interface 里保留不会报错；如需清理等下一轮

## 关键决策

| # | 决策 | 依据 |
|---|---|---|
| 1 | 连 LLM 抽取字段也一起删 | 既然不再判定在读，抽取 `in_school`（布尔）和专门为在读判定新增的 `education_end` 纯属浪费 LLM token；`education_end` 无其他消费方 |
| 2 | 测试 fixture 里的 `"in_school": True` 不动 | 纯粹是噪音、不影响运行；删掉反而多改三行，收益为零 |
| 3 | 不保留「在读状态」作为规则配置项 | 这不是「暂时关闭」，是业务前提变了——默认进入系统的简历都已通过初筛；未来如果要加回来，改 `rules.yaml + rule_engine.py` 即可，但**不应该**让规则文件里留一个永远是 false 的开关 |

## 踩坑

- **Edit 手滑误删了提示词里的 ai_tool_experience 等四条**。old_string 匹配到了「可实习时长」那条 + 后面的 9-13 五条，new_string 只给了一条，导致中间 ai_tool 相关的 4 条提示词被抹掉。补救方法：再 Edit 一次把缺失的四条补回来。教训：old_string 尽量只匹配到一段明确的边界（如一个函数/规则块），不要用逗号式的多条匹配，否则手滑容易漏。
- **ExtractedFields 里删字段要同步删三处**：`state.py` 的 Pydantic 模型、`extract_tools.py` 的提示词（要补编号）、`_JSON_PROMPT` 的键列表。只删模型或只删提示词会导致 `with_structured_output` 与 JSON 回退路径行为不一致。

## 残留问题

- 老记录（新增 `fields_json` 列之前创建的）的 `fields_json` 里本来就可能有 `in_school` / `education_end`，现在 Pydantic 模型已不含这两个键，但 `_row_to_run()` 会 `json.loads(fields_json)` 返回原始 dict，前端 `RunFields` interface 也兼容多余键，所以不会报错。如需彻底清理 DB 里的这两个键值，手动 `UPDATE runs SET fields_json = ...` 即可（非必要）。
- 前端 `ResultCard.fieldNote()` 五个 case 里的 `degree` / `school` / `ai_tool` / `stability` / `days_per_week` 完全没变，因为这些字段本来就不是在读状态相关的。在读状态从来没有出现在评分卡里（它是硬性条件，不是评分维度）。
