# 前端看板重布局：统计看板 + 弹窗化

日期：2026-09-22
涉及模块：backend / frontend

## 需求

按参考图把前端从「左右两栏」改成**单列纵向看板**：

```
┌ 头部：标题 + [历史记录] 按钮 ────────────────┐
├ 4 张统计卡：总简历数 / 推荐简历 / 待复核 / 暂不推进 ┤
├ 状态分布：3 条横向占比条                      │
├ 简历输入模块（最下端）                        │
└──────────────────────────────────────────┘
```

- 顶部统计卡从左到右：总简历数、推荐简历、待复核简历、暂不推进
- 状态分布只保留 3 行：推荐简历 / 待复核简历 / 暂不推进
- 历史记录收成右上角一个按钮，点击弹小窗查看
- 筛选结果也改为弹窗（主页面只留统计 + 输入）
- **四张统计卡可点击**，点哪张弹哪张的名单弹窗（复用历史记录数据）

## 关键决策

| # | 决策 | 依据 |
|---|---|---|
| 1 | **备选算进「推荐简历」** | 好处是 `推荐 + 待复核 + 暂不推进 = 总简历数`，数字能对上 |
| 2 | **结果也用弹窗** | 主页面只剩统计 + 输入，最接近参考图 |
| 3 | **后端新增 `/api/stats` 而非前端自己 count** | `list_runs()` 硬限 50 条，前端 count 在记录超 50 条时会偏小 |
| 4 | `total` 取 `runs` 行数 | 每次 `/agent/run` 都新生成 `candidate_id`，runs 行数 = 简历份数 |
| 5 | 待复核用 `status = 'WAITING_REVIEW'` 判定，**不能用 `rating`** | `rating` 只在完成后写入，中断期间为 `null` |
| 6 | 评级文案从 `load_rules()["labels"]` 取，不硬编码 | `rating` 列存的是中文文案；项目约定「规则外置」 |
| 7 | 结果弹窗与历史弹窗**叠加**，不互相关闭 | antd 自动处理 z-index；关掉结果即回到历史列表，无需额外状态 |
| 8 | `HistoryList` 去 `Card` 外壳而非新建列表组件 | 弹窗内再套 Card 会双层框；改纯列表后两处都能用 |
| 9 | `ResultCard` 加 `embedded` 而非新建组件 | 复用现有评分/说明渲染，避免重复实现 |
| 10 | 统计卡与占比条共用一套语义色 | 推荐=绿 `#16a34a`、待复核=橙 `#f59e0b`、暂不推进=红 `#ef4444`、总=蓝 `#2563eb` |
| 11 | **不做**参考图里的「导出 / 添加投递 / 状态·方向筛选 chips / 导入 / 清空」 | 用户未要求，属另一件事 |
| 12 | 统计卡名单**复用 `HistoryModal`**，不新建组件 | 加一个可选 `title` 即可；列表渲染、点击进详情、叠加结果弹窗的逻辑全都已有 |
| 13 | 名单在**前端过滤**历史记录，不新增后端接口 | 用户明确要求「直接用历史记录中的信息」 |
| 14 | 过滤口径与 `/api/stats` 对齐 | 推荐 = `rating ∈ {推荐进入笔试, 备选}`；待复核 = `status === 'WAITING_REVIEW'`（**不看 `rating`**）；暂不推进 = `rating === '暂不推进'`；总简历数 = 全部 |
| 15 | 头部「历史记录」按钮与「总简历数」卡共用 `listKey='all'` | 两者语义相同（全部简历），一个 state 管到底，避免两个弹窗状态打架 |

## 踩坑与注意

- **`status` 与 `rating` 是两列，语义不同**：`status` 只有 `COMPLETED` / `WAITING_REVIEW`；`rating` 只在完成后写入。统计「待复核」只能看 `status`，看 `rating` 会永远得 0。
- **`list_runs()` 有 50 条上限**：任何「统计总数」的需求都不能在前端基于该接口计算。
- **`HistoryList` 的 `loading` 语义变了**：以前靠 `Card loading` 整块骨架屏，现在改成只在「加载中且列表为空」时显示 `Spin`，避免刷新历史时把已有列表闪没。
- **`RatingModal` 与 `ResultModal` 可同时打开**：`handleSelectHistory` 命中待复核记录时开 `ReviewModal`、否则开 `ResultModal`，两者都不关 `HistoryModal`。
- **`handleResume` 补了「仍需复核」分支**：原实现无条件关 `ReviewModal` 并当成完成，若复核后仍中断会丢失弹窗；现改为按 `status` 分支。

## 残留问题

- 历史弹窗列表仍走 `GET /api/candidates`（上限 50 条）。当前 43 条未触顶，超过后**名单条数会少于卡上数字**——统计数字不受影响（走 `/api/stats` 聚合），但名单需要分页或提高上限，本次未做。
- 「待复核简历」目前只能通过名单弹窗点进去复核，没有单独的复核入口；`/api/review/pending` 接口已存在但前端未用。
- 前端过滤口径的评级文案（`推荐进入笔试` / `备选` / `暂不推进`）是硬编码常量，与 `HistoryList` / `ResultCard` 里已有的 `RATING_COLOR` 映射同源。若 `rules.yaml` 的 `labels` 改文案，这三处都要同步，否则名单会静默变空。
