# 2026-09-22 复核弹窗补齐字段选项

## 问题

前端人工复核弹窗打开后**没有任何可选项**，只有复核原因提示，无法补录。

## 根因

`ReviewModal.buildFields()` 靠 `reasons` 关键词推导要渲染哪些表单项，
但只映射了 4 类关键词，而后端 `validate_node` 能产出 8 类复核原因：

| 后端原因 | 前端是否处理 | 字段 |
|---|---|---|
| 可实习时长缺失 / 处于边界 | ✅ `时长` | `internship_duration_months` |
| 每周到岗天数缺失 | ✅ `到岗天数` | `days_per_week` |
| 是否成都线下缺失 | ✅ `成都` | `chengdu_onsite` |
| 院校层次冲突 / 无法确认 | ✅ `院校` | `school_tier` |
| **在读状态缺失** | ❌ | `in_school` |
| **学历层次缺失** | ❌ | `degree_level` |
| **抽取置信度过低** | ❌ | 无单一字段 |
| **AI工具项目经历缺少证据** | ❌ | `ai_tool_experience` |

### 证据（真实数据）

`runs` 表最近几条 `WAITING_REVIEW` 的 `payload_json.reasons`：

```
C20260922-027  ['在读状态缺失', '学历层次缺失']
C20260922-025  ['学历层次缺失']
C20260922-023  ['学历层次缺失']
C20260922-022  ['学历层次缺失']
```

全部命中「被漏掉」的那几类 —— 所以弹窗是空表单。

`degree_level` 抽取本就非确定性（约 1/6 概率为 `null`，见 `INDEX.md` 已知环境阻塞表），
因此这条路径**高频**触发，不是偶发。

## 用户确认的口径

| 口径 | 选择 |
|---|---|
| 修复范围 | **只补高频两类**：在读状态、学历层次（AI工具证据、置信度过低暂不处理） |
| 学历层次取值 | **只给本科 / 硕士 / 博士**，严格对齐 `rules.yaml` 的 `allowed_degrees` |

## 变更范围

### 修改：frontend/

| 文件 | 变更 |
|---|---|
| `src/components/ReviewModal.tsx` | `buildFields()` 新增 `inSchool`（关键词「在读状态」）与 `degree`（关键词「学历层次」）；`useEffect` 补两个字段初值；`handleOk` 提交 `in_school` / `degree_level`；表单新增「在读状态」`Switch` 与「学历层次」`Segmented`（必填） |

### 未改动

- 后端：`in_school` / `degree_level` 本就在 `ExtractedFields` 里，
  `review_node` 的 `{**state["fields"], **human_input}` 合并逻辑天然支持覆盖，无需改动
- `rules.yaml`：`allowed_degrees: [bachelor, master, phd]` 未动

## 关键决策

### 1. 学历选项严格对齐 `allowed_degrees`，不加「其他」

若候选人是大专等，本来就该被硬性条件淘汰，不需要人工在弹窗里表达 —— 不加「其他」选项。

### 2. `in_school` 用 `Switch` + `valuePropName="checked"`

后端判定是 `hard["require_in_school"] and not fields.get("in_school")`，
即**布尔真值**语义。`Switch` 直接产出 `true/false`，不引入字符串映射。

### 3. 未处理的 2 类原因不静默

「抽取置信度过低」「AI工具项目经历缺少证据」仍然没有对应表单项（用户口径 B）。
这两类在弹窗里只体现为「复核原因」文案，**不会**因此提交空对象以外的内容 ——
但 `handleOk` 至少会在用户填写了其他项时正常提交。
若后续高频出现，按同样方式补 `ai_tool_experience` 即可。

## 遗留风险

- 「抽取置信度过低」触发时，弹窗仍无对应可编辑项（用户明确选择暂不处理）
- 后端若新增复核原因字符串，前端 `buildFields()` 需同步 —— 这个耦合点
  已在 `INDEX.md` 记录为已知约束
