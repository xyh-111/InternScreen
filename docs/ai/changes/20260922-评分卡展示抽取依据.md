# 筛选结果评分卡展示抽取依据

日期：2026-09-22
涉及模块：backend / frontend

## 需求

「筛选结果」里 5 个评分小卡片原来只有标签 + 分数，看不出这个分是怎么来的。要求在每张卡下方补一行灰色小字，显示打分依据：

| 卡片 | 依据文案 | 数据来源字段 |
|---|---|---|
| 学历 | `本科` / `硕士` / `博士` / `其他` | `degree_level` |
| 院校 | 院校名，多段学历用 ` / ` 连接 | `graduate_school` / `bachelor_school` |
| AI 工具 | `项目经历` / `日常对话` / `无` / `未知` | `ai_tool_experience` |
| 到岗稳定性 | `可实习 6 个月` | `internship_duration_months` |
| 每周到岗 | `每周 5 天` | `days_per_week` |

## 关键事实

**抽取结果 `fields` 原本根本不在接口返回里。** `_completed_response()` 只返回 `score` / `hard_filter` / `explanation` / `trace`，`fields` 仅存在于 `interrupt_payload`（中断态）中。而 `trace` 里 `extract_node` 只记了 `missing_fields`，不含字段值——所以**前端无法从现有响应里推出依据**，必须动后端。

## 改动清单

### 后端

| 文件 | 改动 |
|---|---|
| `backend/app/services/storage.py` | `runs` 表新增 `fields_json` 列；`init_db()` 加老库补列迁移；`save_run()` 加 `fields` 参数；`_row_to_run()` 返回 `fields` |
| `backend/app/api/agent.py` | `_completed_response()` 加 `"fields"`；`_persist()` 传 `fields=result.get("fields")` |

### 前端

| 文件 | 改动 |
|---|---|
| `frontend/src/types/index.ts` | 新增 `RunFields` 接口；`RunView` 加 `fields?: RunFields \| null` |
| `frontend/src/components/ResultCard.tsx` | 新增 `fieldNote()` 映射函数与 `DEGREE_LABEL` / `AI_TOOL_LABEL` 字典；评分格里渲染 `.is-score-note` |
| `frontend/src/styles.css` | 新增 `.is-score-note` |

## 关键决策

| # | 决策 | 依据 |
|---|---|---|
| 1 | **必须落库**（新增 `fields_json` 列），不能只加进接口响应 | 结果弹窗既从「刚跑完的运行」打开，也从「历史记录」打开。只加响应的话，历史里的记录点开就没有依据小字，同一个弹窗两种表现 |
| 2 | 用 `ALTER TABLE` 迁移而非重建表 | 已有 43 条历史记录不能丢；`CREATE TABLE IF NOT EXISTS` 不会改已存在的表，所以 `init_db()` 里显式查 `PRAGMA table_info` 补列 |
| 3 | 依据**不进 `trace`**，单独存字段 | `trace` 是给终端日志用的逐节点流水，语义不同；把 `fields` 塞进去会让 trace 体积翻倍（含 `evidence` 原文） |
| 4 | 字段缺失时**不渲染**该行小字，而不是显示 `—` | 老记录没有 `fields`，显示 5 个 `—` 比不显示更难看 |
| 5 | 院校卡显示**院校名**而非层次 | 用户明确要求「院校中加入院校名」。分数为什么是 20 分（双一流）已由下方解释段落覆盖 |
| 6 | 多段学历用 ` / ` 连接且研究生在前 | 研究生的层次通常决定最终得分，放前面更贴近阅读顺序 |

```js
{ modals: 2, notes: ["硕士", "电子科技大学 / 四川大学", "项目经历", "可实习 6 个月", "每周 5 天"] }
```

5 条依据与预期逐字一致。旧记录（无 `fields`）点开 `notes` 返回 `[]`，即不显示依据行。控制台无 error。

## 残留问题

- **老记录没有依据小字**。`fields_json` 是新增列，此前 43 条记录的该列为 `NULL`，且无法从 `trace` 反推（`trace` 不含字段值）。如需补齐只能重跑。
- `degree_level` / `in_school` 本身有 10-25% 抽取空率（既有问题），空值时「学历」卡的依据行不显示，与老记录表现相同、无法区分。
- 依据文案（`本科` / `硕士` / `项目经历` 等）是前端硬编码枚举映射，与 `state.py` 的 `DegreeLevel` / `AIToolExperience` 枚举同源。后端枚举改动需同步 `ResultCard.tsx` 的两个字典。
