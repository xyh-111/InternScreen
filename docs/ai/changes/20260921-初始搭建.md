## 关键决策与踩坑

### 1. Checkpointer 必须模块级单例（修正文档缺陷）

文档第 5 节在 `build_screening_graph()` 内部 `MemorySaver()`，而 6.2 节 `resume_review()` 又新建图。
两次调用拿到两个不同的 checkpointer，`thread_id` 找不到 → `Command(resume=...)` 必然失败。

**做法**：`app/memory/checkpointer.py` 暴露 `CHECKPOINTER` 单例；`build_screening_graph()` 加 `@lru_cache(maxsize=1)`。

### 2. 规则外置，节点零分数常量

文档 4.5 把分数硬编码在 `screen_node`，与验收标准 8「规则仍由 rules.yaml 控制」冲突。
**做法**：`app/services/rule_engine.py::run_rules()` 读 `app/config/rules.yaml`，`screen_node` 只调用并写状态。
`validate_node` 的阈值同样来自 `rules.yaml` 的 `validation` 段。

### 3. 样例简历分数口径（反推自 rules.yaml）

| 样例 | 字段组合 | 计算 | 结果 |
|---|---|---|---|
| 甲 陈某 | master + double_first_class + project + 6月 + 5天 | 25+20+25+15+15 +5 | 105 |
| 乙 刘某 | master + other + project + 4月 + 4天 | 25+8+25+10+12 | 80 |
| 丙 张某 | 缺失时长/天数/成都线下 → 复核后补 3月/4天/成都 | 25+8+25+10+12 | 80 |

注意：乙必须是 **project** 级 AI 工具经历（25 分）而非 `daily_chat`（12 分），否则只有 67 分。

### 4. 环境：pip 全局安装被沙箱拒绝

`python -m pip install` 写入 `C:\Users\hxy\AppData\Roaming\Python\Python311` 被沙箱拦截。
**做法**：改用项目内 venv（`backend/.venv`），安装路径落在可写目录内。

### 5. 实际安装的依赖是 langchain 1.x / langgraph 1.x

计划里按文档写的 `langchain>=0.3` 实际解析到了 **langchain 1.4.2 + langgraph 1.2.11**。
已逐项验证 `StateGraph` / `add_messages` / `MemorySaver` / `interrupt` / `Command` 在该版本下 API 不变，
并把实测版本回写进 `requirements.txt`。

### 6. `DASHSCOPE_MODEL` 默认值修正

计划里写的 `qwen3.8-max` **在 DashScope 上不存在**，实测返回
`400 InvalidParameter: url error`。已实测可用：`qwen-plus` / `qwen-max` / `qwen-turbo` / `qwen3-max`，
默认值改为 `qwen-plus`。

### 7. `school_tier` 缺失时静默得 0 分（已修）

首次通过 HTTP 跑乙时得到 **72 分**而非 80，定位为 LLM 对「成都信息工程大学」返回 `school_tier: null`，
而 `scoring.school_tier.get(None, 0)` 命中默认值 0。
文档 4.5 的原始语义是「双一流 20，**否则 8**」，故：
- `rules.yaml` 的 `school_tier` 增加 `unknown: 8`
- `rule_engine` 改为 `.get(fields.get("school_tier") or "unknown", 0)`
- 新增回归用例 `test_missing_school_tier_still_scores_8`

### 8. 前端 AntD 静态 message 警告（已修）

浏览器控制台报 `message` 静态方法缺少 App 上下文。已在 `App.tsx` 包 `<AntApp>`，
`Dashboard` / `CandidateInput` 改用 `App.useApp()`。
