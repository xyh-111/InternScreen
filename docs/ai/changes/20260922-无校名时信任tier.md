# resolve_school_tier：无真实校名时直接信任 LLM tier

**日期**：2026-09-22
**涉及模块**：backend（`services/rule_engine.py`）
**用户诉求**：简历只提"双一流/非双一流/普通高校"等 tier 标签（无具体校名），`resolve_school_tier` 仍试图用名单比对 → 名单未命中 + LLM tier=double_first_class 被判冲突 → 错误触发人工复核。

---

## 1. 问题

上一轮修了 `_sanitize_school_names()`，把 tier-only 校名置空 + 推断 tier。现在字段正确了：

```python
{
    "bachelor_school": None,
    "bachelor_school_tier": "double_first_class",
}
```

但 `resolve_school_tier` 仍走原判定表第 7 行：

| list_hit | llm_hit | tier | review_reason |
|---|---|---|---|
| False | True | other | "冲突：抽取结果为双一流，但名单未命中" |

**为什么这是 bug**：名单无法对 `None` 做判定。当所有校名字段都为空，名单**没有**给出任何结论 → 也就不存在"名单 vs LLM"的冲突。冲突校验只有在**名单确实给出过结论**（命中 / 独立学院）时才有意义。

## 2. 修复

在 `resolve_school_tier()` 最前面（override 之后、list_verdicts 之前）加前置分支：

```python
has_real_school = any(
    fields.get(f) and str(fields.get(f)).strip()
    for f in _SCHOOL_FIELDS
)
```

- **有真实校名** → 走原有名单先判 + LLM 一致性校验（不变）
- **无真实校名** → 名单无输入可查 → 直接信任 LLM tier
  - `llm_hit` → `double_first_class`，无复核
  - `llm_says_other` → `other`，无复核
  - 两者都空 → 仍需复核（两边都无信息）

## 3. 改动

| 文件 | 改动 |
|---|---|
| `rule_engine.py` `resolve_school_tier` | 前置分支 ~15 行 |
| `test_rule_engine.py` | 新增 5 个测试：无校名 + llm_hit / llm_other / 两边空 + 任一校名触发名单路径 + 端到端 run_rules 得分 |

## 4. 验证

pytest **37 passed**（原 32 + 新增 5）。

端到端验证脚本：

```
无校名 + llm_hit → tier=double_first_class, review_reason=None ✓
run_rules → school_score=20, final=105  ✓
有校名 + list_hit → 路径不变 ✓
```

## 5. 边界

| 场景 | has_real_school | 路径 | 复核 |
|---|---|---|---|
| 四川大学（名单命中）| True | 名单先判 | 否 |
| 四川大学锦江学院（独立学院） | True | 名单先判 + LLM 比对 | 仅 LLM 判 double 时 |
| None + tier=double_first_class | **False** | **信任 LLM** | **否**（修复点） |
| None + tier=other | False | 信任 LLM | 否 |
| None + tier=None | False | 两边都空 | **是**（确实无法确认）|

**一个容易忽略的场景**：`bachelor_school=None + graduate_school="清华大学"` → `has_real_school=True` → 走名单路径。这是正确的：有任何一段真实校名都要查名单。

## 6. 决策记录

1. **has_real_school 定义宽松**：`str(f).strip()` 只要非空就算，不检查是不是 tier 标签。由上游 `_sanitize_school_names` 保证校名字段是真实校名（tier-only 已置空）。
2. **前置分支位置**：在 `override` 之后、`list_verdicts` 之前。人工 override 优先级最高（不变）。
3. **run_rules 自动受益**：它调用 `resolve_school_tier()["tier"]` 做评分，tier 判对了 → `school_score=20`（名单时是 20，其他是 8）。无需改动 run_rules 本身。
